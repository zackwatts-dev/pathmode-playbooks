# Go-live checklist

## Before it runs for real

- [ ] It passed the pass mark on your own suppliers, including the part held back (`pass-mark.md`).
- [ ] It runs on a server you control, with a log line for every run.
- [ ] Access to the ERP exports and the agreement folders is read-only. Checked, not assumed.
- [ ] The AI key is in the server's secret store, nowhere else, under an API account whose terms say your data isn't used for training.
- [ ] The dashboard lands where only purchasing, the controller and the CFO can open it.
- [ ] Every agreement, amendment and program email is in its supplier's folder.
- [ ] Today's numbers are written down: rebates, co-op and allowances recovered last year, and how many statements were checked.

## The first year: two or three suppliers

- [ ] Start with the suppliers purchasing knows best. Compare every term it read with the agreement by hand.
- [ ] Every item sent to a person gets a decision, and every claim a result (paid, disputed, or withdrawn).
- [ ] Each result becomes a case in the answer key.
- [ ] Extend to the rest only when the terms and claims have stayed clean.

## After the switch

- [ ] Each year, once the statements arrive: run it, review every claim, send the letters.
- [ ] Whenever a new agreement or amendment arrives: run it for that supplier.
- [ ] Every claim's outcome recorded; the running count of claims withdrawn is the number to watch.
- [ ] Whenever the AI model or a prompt changes: score against the answer key again before it goes back into service.
- [ ] After a year: measure the same numbers as before go-live, and decide to keep it, extend it, or stop.
