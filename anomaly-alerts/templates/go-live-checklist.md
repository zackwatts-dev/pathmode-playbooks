# Go-live checklist

## Before it runs for real

- [ ] It passed the pass mark on your own records, including the part held back (`pass-mark.md`).
- [ ] It runs on a server you control, every morning, with a log line for every run.
- [ ] Access to every export is read-only. Checked, not assumed.
- [ ] The AI key is in the server's secret store, nowhere else.
- [ ] Each brief lands in a folder only its owner can open.
- [ ] Someone gets an alert if no brief appears, or an export goes missing.
- [ ] Today's numbers are written down: losses found in the last year, and how long each ran before it was found.

## The first month: two locations

- [ ] Two locations whose managers want it get a brief every morning.
- [ ] They mark every flag real or not, and every item for a person gets an answer.
- [ ] Each mark becomes a case in the answer key.
- [ ] Extend to the rest only when the marks have stayed clean for [a month].

## After the switch

- [ ] Every morning: each manager reads their brief.
- [ ] Every flag marked real or not; the running count of false alarms kept.
- [ ] Monthly: read the false alarms and the items for a person together. A new kind of honest odd day? A threshold too tight?
- [ ] Whenever the AI model or a prompt changes: score against the answer key again before it goes back into service.
- [ ] After six to twelve months: measure the same numbers as before go-live, and decide to keep it, extend it, or stop.
